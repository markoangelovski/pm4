## Implementation notes
_Implementer: what changed, and anything the reviewer should look at._

- `lib/auth/token-store.ts`: try/catch around every `localStorage` access (D5). Local set/clear notify an
  in-module listener set (a tab gets no `storage` event for its own writes); `subscribe` adds those plus
  `storage` events for the key. `useHasStoredSession` = `useSyncExternalStore` with a `null` server snapshot.
- `lib/auth/session.ts`: a second, unauthenticated openapi-fetch client (D8). Single-flight `inFlight`
  promise wrapping `navigator.locks.request("pm4-auth-refresh", …)` when present; the stored token is read
  inside the lock (D7). Cache reused until `expiresAt - 30 s` (D6). The D13 code map lives here:
  `exchangeLoginCode` returns the same promise for a code already exchanged on this page load, so T2's
  callback gets Strict Mode safety for free.
- A `generation` counter is bumped on sign-out, session end and removal elsewhere; a refresh that
  answers `200` after that stores nothing and returns `null` (prevents a late refresh from re-storing a
  token after sign-out). Not in the spec; small, reviewer should confirm it's welcome.
- Refresh statuses other than 200/400/401 (e.g. 403) are treated like 5xx/429 (`SessionUnavailableError`,
  session kept). The spec names only 5xx/429 and thrown fetches.
- `lib/api/client.ts`: `authFetch` per the spec; the bearer is set on a `new Request(request)` copy, the
  retry uses `request.clone()` taken before the first send.
- `npm run api:types`: no diff (the auth paths were already generated by T-0017).
- Browser time zone in `googleSignInUrl` comes from `Intl.DateTimeFormat().resolvedOptions().timeZone`
  (no `lib/time` helper exists for it, and `lib/time` isn't in this task's files).

## Review
_Filled in by `review-feature`._

**Verdict: approve** (Opus reviewer, feat-auth-web-session; `pm4 check --feature` PASS). Minor findings:

1. The `generation` guard (`session.ts`) isn't in the spec. Keep it: the dropped token is already revoked
   server-side. Follow-up: one sentence in the spec's refresh paragraph (main session).
2. A refresh that starts during `signOut()`'s logout await can re-store a (revoked) token after
   `clearRefreshToken()`, so the landing shows "Go to app" until a refresh 401. Fix: bump `generation` and
   reset `cached` again right after `clearRefreshToken()` in `signOut`.
3. Statuses other than 200/400/401 → `SessionUnavailableError`, session kept. Accepted (follows D1).
   Follow-up: add "any other status" next to 5xx/429 in the spec. No code change.

Tier feedback: opus was right (cross-tab locking, single-flight, late-refresh races).
